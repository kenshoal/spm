## Approved contract

Normalised user story: responsible arrangement staff and the current coordinator need durable, specific review work when an accepted event change, equipment unavailability or an explicit safety instruction invalidates existing arrangements.

- **AC1:** Given eligible existing arrangements, when a significant event change or reschedule is accepted, then each affected arrangement receives its own durable review flag with the real trigger, changed fields, reason and time.
- **AC2:** Given existing arrangements/review work, when an unrelated edit or semantic no-op occurs, then review state is preserved without spurious flags or notifications.
- **AC3:** Given a newly raised review trigger, when it commits, then the appropriate domain queue of current role-holder accounts and current coordinator receive deduplicated notifications; retries retain stable notice identity.
- **AC4:** Given a named outstanding review, when authorised same-domain staff completes it, then clearing records who/when without clearing a newer trigger or erasing original evidence.
- **AC5:** Given the current assigned coordinator, when outstanding reviews are requested, then a complete protected list is returned, and readiness consumers share the same outstanding-review truth.
- **AC6:** Given current/future reservations for equipment that becomes unavailable, when its authorised operational update is accepted, then affected reservations receive review work without rewriting their statuses.
- **AC7:** Given explicit affected arrangement targets, when the Safety Officer requests a recheck, then the targets receive safety_recheck flags/reason; SCRUM-64 makes no event lifecycle transition.

Operational rules approved by the delegated requester/root: proposed_date_times and expected_attendance affect venue+equipment; venue_requirements affects venue only; equipment_requirements affects equipment only. Compare semantic normalised values, not raw equivalent date/text representations. Ordinary venue selection requires Approved booking and end_date>=today; reservations use equipment_id/requirement_id linkage and return_date>=today; the Asia/Singapore final day is inclusive. Event must not be terminal. Pending venue requests are not an ordinary approved booking. DAMAGED/UNDER_REPAIR/UNDER_MAINTENANCE/RETIRED trigger equipment review; restoring AVAILABLE never auto-clears review work.

Review flags are separate per trigger and arrangement. All authorised staff of that domain can clear, including someone who did not create/edit the arrangement. Staff directories use the existing authoritative role logic including existing metadata fallback only when staff_roles is empty (not a union); this does not grant callers new admin access. Role queues resolve current role-holder accounts under existing authentication rules; no new active_staff flag is assumed. Queues plus the current coordinator deduplicate overlapping recipients. Preserve existing event-change uuid5 identity `needs-review:{change_request_id}:{arrangement_id}`; other triggers use stable actual trigger UUIDs, never fabricated change-request IDs. Delivery is post-commit and retry-safe. Actual event/operational-update, flag and required enqueue atomicity, named clearing and shared outstanding facts are verified separately below. Future consuming workflow lock/readiness decisions and saved-safety caller integration remain unverified.

First read API: `GET /event-requests/{event_id}/arrangement-reviews` returns a JSON LIST of OUTSTANDING rows, newest absolute raised_at then UUID ID descending. Each row has id/event_request_id/arrangement_id/trigger_id UUIDs, arrangement `venue_booking` or `equipment_reservation`, trigger_type `event_change`/`equipment_unavailable`/`safety_recheck`, changed_fields list[str], reason str, timezone-aware raised_at and null cleared_at/cleared_by. Current assigned coordinator only: owner/domain-only staff 403 `ARRANGEMENT_REVIEWS_FORBIDDEN`; unrelated/former coordinator 404 `ARRANGEMENT_REVIEWS_NOT_FOUND`; absent auth401 existing Authentication required; read failure502 Arrangement reviews unavailable. Domain staff use their implemented arrangement-scoped queues without event-wide access expansion. Safety Review remains nonterminal and retains exactly the same current-assignment boundary; Safety Officer capability alone does not grant this view. Coordinator persistence uses service-only get_outstanding_arrangement_reviews(uuid), returning full event-scoped outstanding rows, not a readiness verdict.
